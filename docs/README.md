# XS guides

[extremespecification.com](https://extremespecification.com) presents the method in one page; [PROTOCOL.md](../PROTOCOL.md) states the rules. The skills (`skills/`) are the procedures agents follow. These guides walk through the setup and one worked example, one phase per page, and name the [level](../PROTOCOL.md#levels) each one needs.

| Guide | Result |
|---|---|
| [Getting started](getting-started.md) (levels 1–3) | a repo prepared for XS and a first task landed |
| [Define a spec](define-a-spec.md) (level 1) | a one-page spec that satisfies the readiness gate |
| [Build and land](build-and-land.md) (levels 2–3) | the tasks of a spec built, reviewed and on `main` |
| [Leave it running](leave-it-running.md) (level 3) | hours of work while nobody answers, and a one-page report when the owner returns |
| [Improve the method](improve-the-method.md) (levels 3–4) | rule proposals decided and the core numbers recorded |
| [Adopt in a team](adopt-in-a-team.md) (level 4, experimental) | the experimental rules for several people |
| [Reference](reference.md) | every command, setting, environment variable and event |

## Worked example

The guides follow one illustrative example: a billing application adds a CSV export of invoices.

- The spec `S04-invoice-csv-export.md`: [Define a spec](define-a-spec.md#the-spec).
- The tasks `T41` to `T44`: [Define a spec](define-a-spec.md#the-tasks).
- One chain from brief to landing: [Build and land](build-and-land.md#one-chain-end-to-end).

## Reading order

Read the first three guides, then the others as needed. Read [Adopt in a team](adopt-in-a-team.md) only when more than one person works in the repo.
